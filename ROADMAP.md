# MileON Auto: Roadmap Разработки

Состояние на 29 октября 2026 года. Репозиторий остаётся
[`kingofgeorgia/georgiancarbenefits`](https://github.com/kingofgeorgia/georgiancarbenefits).
MileON Auto используется как рабочее название продукта; переименование репозитория
и интерфейса не входит в этот план автоматически.

Документ описывает следующие этапы разработки, а не обещанные сроки выпуска.
Статус «реализовано» ниже относится к коду и прежним проверкам, а не к готовому
публичному production-развёртыванию. Новая последовательность DEV-1...DEV-6
не меняет нумерацию исторических PR и отчётов.

## Точка Отсчёта

| Возможность | Подтверждённое состояние |
| --- | --- |
| MyAuto URL/ID и VIN | Реализованы; есть автоматические сценарии загрузки, ошибок и восстановления |
| ICE, Hybrid, Series Hybrid, EV | Расчётные пути и налоговый breakdown реализованы; правила нужно проверять на дату оформления |
| Share Deal и WhatsApp CTA | Реализованы; публичная ссылка и контекст автомобиля проверялись |
| Подбор по бюджету | Реализованы режимы покупки в Грузии и полной стоимости до России, без Drom |
| Дата производства и VIN-комплектация | Поле MM/YYYY с маской и календарём; неопределённая комплектация скрыта |
| Собственный справочник | Данные и внутренние механизмы есть; публичный выбор и панели источников скрыты по решению владельца |
| Защита публичного API | Базовые квоты, ограничения запросов и внешних URL реализованы; новые интеграции требуют своей проверки |
| Эксперимент OpenAI | Опубликованы протокол, 10 черновых сценариев и шаблон запроса; исполнителя и результатов API пока нет |
| Production | Конфигурация и инструкции есть; действующий публичный запуск не подтверждён |

Контекст последней публикации: [PR #30](https://github.com/kingofgeorgia/georgiancarbenefits/pull/30).
Прохождение CI с тестовыми ответами поставщиков не подтверждает доступность
живых MyAuto, VIN, валютного или будущего OpenAI API.

## Очередь Этапов

| Этап | Приоритет | Статус | Зависимость |
| --- | --- | --- | --- |
| DEV-1. Проверить поиск характеристик через OpenAI | Следующий | Подготовка; реальный прогон не начат | Локально настроенный ключ, эталоны, бюджет |
| DEV-2. Добавить помощника поиска характеристик | После DEV-1 | Не начат | Отдельное согласие и положительное решение по пилоту |
| DEV-3. Расширить проверенный справочник | После оценки источников | Не начат | Политика проверки записей; может наполняться вручную без OpenAI |
| DEV-4. Доработать подбор по бюджету | Перед beta | Базовый функционал есть; доработка не начата | Проверенные характеристики либо явный статус нехватки данных |
| DEV-5. Итоговая проверка beta | Перед публикацией | Повторный релизный прогон не начат | Согласованный набор функций релиза |
| DEV-6. Публичная beta и обновления | После DEV-5 | Не начат | Разрешение на публикацию, инфраструктура и восстановление |

Ни одна AI-функция не является обязательным условием выпуска: при отрицательном
результате DEV-1 можно согласовать beta с ручным вводом и существующими источниками.

## DEV-1. Проверить Поиск Характеристик Через OpenAI

**Цель:** понять, что можно достоверно извлечь из документа и что реально найти
по доступным сведениям MyAuto/VIN, не изменяя публичный калькулятор.

Основа: [протокол эксперимента](experiments/openai-characteristics-pilot/README.md),
[выборка](experiments/openai-characteristics-pilot/cases.json),
[шаблон запроса](experiments/openai-characteristics-pilot/prompt.txt).

- [ ] Настроить API-ключ только локально, без публикации в Git, переписке и журналах.
- [ ] Дособрать эталоны: 10 сценариев пока не являются 10 полностью проверенными автомобилями;
  для пяти сверены лишь отдельные факты. Для EV и последовательных гибридов нужны
  применимые документы с явно указанной 30-минутной мощностью.
- [ ] Подготовить изолированный исполнитель: ограничения поиска, токенов, времени,
  числа запросов и консервативный учёт затрат, включая ошибки и повторные попытки.
- [ ] Проверить исполнитель без сети: отсутствие ключа, исчерпание бюджета,
  неподтверждённые источники, конфликт модификаций и смешение типов мощности.
- [ ] Раздельно испытать разбор заранее заданного документа и самостоятельный поиск.
  Не передавать модели эталонный ответ; не смешивать истории двух испытаний.
- [ ] Начать с 1-2 реальных сценариев. Остальные запускать только при обоснованной
  верхней оценке затрат в пределах общего разрешённого бюджета **1 USD**.
- [ ] Проверить ответы по оригиналам: значение, исходная единица, тип мощности,
  рынок, версия, год применимости, документ и страница/раздел.
- [ ] Опубликовать обезличенный отчёт: проверенные и непроверенные случаи, ошибки,
  корректные отказы, время, токены, инструменты, расходы и рекомендация продолжать или отложить.

**Готово, когда:** реальный прогон выполнен и проверен, либо невозможность его
выполнить задокументирована и владелец явно решил отложить направление.
Отсутствие ключа или публикация протокола сами по себе не завершают эксперимент.
Небольшая выборка не доказывает пригодность к автоматическому массовому применению.
При нехватке бюджета остановиться с частичным отчётом, а не увеличивать лимит.

**Текущее разрешение:** только изолированный пилот с бюджетом 1 USD.
Внедрение результатов в сайт и переход к DEV-2 требуют отдельного согласия.

## DEV-2. Добавить Помощника Поиска Характеристик

**Цель:** пользователь может запросить недостающие характеристики и увидеть
обоснованный результат, сохраняя возможность ручного ввода.

- [ ] Согласовать объём первой версии по результатам DEV-1, включая допустимые источники.
- [ ] Добавить отдельное действие поиска, состояния ожидания, отмены, ошибки и повторной попытки.
  Не выполнять скрытые платные запросы при обычной загрузке MyAuto/VIN.
- [ ] Показывать число, единицу, тип мощности, оригинальный источник и границы применимости;
  при неоднозначности запрашивать уточнение вместо выбора произвольной версии.
- [ ] Разделить кандидата AI, проверенный факт и применимое к автомобилю значение.
  Подтверждение кнопкой пользователем не заменяет проверку применимости документа.
- [ ] Не заменять документально подтверждённые поля неподтверждённым ответом модели.
  При изменении идентичности автомобиля сбрасывать прежнюю AI-привязку и устаревший расчёт.
- [ ] Добавить серверные лимиты стоимости и запросов, таймауты, безопасную работу с
  внешними документами, защиту от SSRF и инструкций внутри найденных материалов.
- [ ] Согласовать передачу VIN/документов внешнему сервису; минимизировать и обезличивать
  данные. Ключи остаются серверными; содержимое документов и секреты не попадают в логи.
- [ ] Добавить тесты успешного поиска, отказа, конфликта, недоступности провайдера,
  квот и RU/EN/KA на мобильных экранах. Предусмотреть отключение AI-функции.

**Готово, когда:** источники и сопоставление проверяемы, ошибки не заполняют налоговые
поля, ручной сценарий работает без OpenAI, CI проходит и владелец принял результат.

## DEV-3. Расширить Проверенный Справочник

**Цель:** повторно использовать проверенные характеристики без повторной оплаты поиска.

- [ ] Определить процесс ручной проверки и добавления записей, не доверяя ответу AI автоматически.
- [ ] Для каждой записи сохранять источник, дату проверки, рынок, диапазон годов,
  точную модификацию, исходную единицу и тип мощности; не расширять применимость догадкой.
- [ ] Отделить справочные сведения производителя от данных, пригодных для конкретного
  автомобиля и расчётного поля; настроить точное сопоставление и отказ при неоднозначности.
- [ ] Добавить происхождение, версию, исправление, снятие подтверждения и повторную
  проверку записи; кеш не должен скрывать исправленный или недействующий источник.
- [ ] Проверять права использования источников; не копировать закрытую коммерческую базу.
  Не помещать персональные VIN-документы в публичный Git или общий справочник.
- [ ] Сохранить публичный справочник скрытым до отдельного разрешения владельца.

**Готово, когда:** каждая используемая запись прослеживается до проверенного источника,
а тесты исключают ошибочное совпадение версии, единицы, рынка и типа мощности.
См. [текущую спецификацию справочника](docs/vehicle-specifications.md).

## DEV-4. Доработать Подбор По Бюджету

**Цель:** сделать существующий подбор понятным и надёжным при реальных неполных объявлениях.

- [ ] Проверить раздельно бюджет только на покупку в Грузии и бюджет на полную
  стоимость до России. Подбор не зависит от Drom и не вызывает его API.
- [ ] По обратной связи уточнить фильтры и сортировку, без обещания полного охвата рынка.
- [ ] Проверить breakdown: покупка, доставка, таможенные платежи, утильсбор,
  брокер/документы/регистрация; не дублировать расходы и не изобретать универсальную цену услуг.
- [ ] Показать, что известно, что введено пользователем, что оценено диапазоном,
  а что требует уточнения. Автомобиль с неизвестной расчётной мощностью не объявлять
  подходящим под бюджет; отдельно предлагать уточнение характеристик.
- [ ] Перепроверить границы бюджета, валюты, возрастные диапазоны, изменение фильтров,
  отсутствие результатов, устаревшие объявления и ошибки поставщиков на desktop/mobile RU/EN/KA.

**Готово, когда:** итоговая сумма воспроизводится из breakdown, ограничения данных
видимы, оба режима проходят проверки, и пользовательские расходы не выдаются за официальные тарифы.
См. [реализованный бюджетный сценарий](docs/budget-selection.md).

## DEV-5. Итоговая Проверка Перед Beta

**Цель:** проверить согласованный релиз целиком после новых изменений.

- [ ] Пройти MyAuto URL/ID, VIN, доступную/отсутствующую комплектацию и дату производства.
- [ ] Проверить ICE/Hybrid/Series Hybrid/EV, breakdown, валюты и пограничные даты;
  заново сверить применимые правила с официальными источниками на дату теста.
- [ ] Проверить оба бюджетных режима, Share Deal без авторизации, неизменяемость
  сохранённой сделки и WhatsApp CTA с правильными данными.
- [ ] Проверить ошибки/восстановление, квоты и недоступность поставщиков;
  отдельно проверить AI, если он включён в релиз, и полное отключение AI.
- [ ] Выполнить автоматический E2E с фикстурами и ограниченный ручной smoke-test
  живых поставщиков. Не выдавать прохождение фикстур за проверку живых сервисов.
- [ ] Пройти 5-10 документально проверяемых автомобилей, desktop/mobile RU/EN/KA;
  приложить обезличенные снимки и перечень проверенных сценариев.
- [ ] Зафиксировать версию кода, известные ограничения, нерешённые дефекты и решение о релизе.

**Готово, когда:** нет незакрытых дефектов, искажающих расчёт, идентичность автомобиля,
сохранённую сделку или безопасность; обязательные проверки зелёные, ограничения приняты владельцем.

## DEV-6. Публичная Beta И Обновления

**Цель:** безопасный ограниченный запуск, а не только наличие Docker-конфигурации.

- [ ] Согласовать хостинг, домен, доступ, операционные расходы и объём beta.
- [ ] Развернуть production-стек с HTTPS, безопасными секретами, внутренними
  PostgreSQL/Redis/API и проверенными настройками браузерного API и CORS.
- [ ] Настроить автоматические резервные копии вне репозитория; проверить восстановление
  на отдельной базе. Резервная копия без пробного восстановления не закрывает этот пункт.
- [ ] Настроить health-check, мониторинг ошибок, уведомления и журналы без секретов
  и лишних персональных данных; проверить недоступность Redis и внешних поставщиков.
- [ ] Подготовить обновление и откат проверенной версии. Перед миграцией делать backup;
  учитывать совместимость схемы при откате, не удалять постоянные тома.
- [ ] Согласовать, затем настроить доставку только прошедших CI версий из main;
  держать production-секреты вне Git, ограничить доступ процесса обновления.
- [ ] Повторить smoke-test по HTTPS и получить явное разрешение открыть beta.

**Готово, когда:** проверены HTTPS, расчёт, сохранение/чтение данных, восстановление,
откат и мониторинг; есть инструкция обновления и решение владельца о публикации.
Основа уже подготовлена в [production-инструкции](docs/production.md) и
[описании защиты API](docs/public-api-protection.md).

## Отдельные Направления

**Windows как локальный тестовый сервер:** Git и Docker проверены пользователем;
успешный запуск проекта, доступ по LAN и удалённое управление ещё не подтверждены.
Это отдельная инфраструктурная задача, не замена roadmap разработки и не обязательное
условие DEV-1. Использовать отдельную базу и проверенную main. Удалённый доступ,
изменения брандмауэра и автоматическое обновление требуют отдельного разрешения.

**Drom:** необязательная ветка развития после официального согласования доступа.
Не блокирует расчёт, бюджетный подбор и beta. Не включать провайдер без разрешения
на использование данных; не заменять официальный доступ обходом ограничений.
См. [провайдер рынка РФ](docs/russian-market-provider.md).

## Правила Работы И Отчётности

- Разработка: отдельная ветка, PR, CI, ревью и объединение в main после проверок.
  Незавершённые изменения не выкладываются на тестовый или публичный сервер автоматически.
- После каждого этапа: короткий отчёт, что сделано, что реально проверено,
  известные ограничения, расходы при наличии, ссылки на PR/CI и результат принятия.
- К следующему этапу переходить только после явного согласия пользователя.
  Само утверждение roadmap не разрешает внедрение всех перечисленных функций.
- Платные запросы и увеличение бюджета согласовываются отдельно; секреты не публикуются.
- Не изменять налоговые правила без проверки первичных источников и регрессионных тестов.
- Не выполнять `docker compose down -v`, не удалять данные и не открывать публичный доступ
  в рамках обычного запуска, проверки или обновления.
- Обновлять статусы и ссылки этого roadmap по результатам выполненных этапов,
  не отмечать подготовку или наличие конфигурации как завершённый запуск.
