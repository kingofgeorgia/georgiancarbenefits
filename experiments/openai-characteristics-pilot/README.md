## Два Разных Испытания

1. Разбор источника: передать модели идентичность и заранее выбранный документ,
   но не эталонный ответ. Проверить число, единицу, тип мощности и место в документе.
2. Поиск: передать только идентичность автомобиля, без эталона и подсказки-источника.
   Проверить найденный оригинал, его применимость и извлечённое значение отдельно.

Для одного автомобиля результаты этих испытаний не смешивать. Извлечение из
заданного документа не доказывает способность найти этот документ по VIN/MyAuto.
Не проводить второй этап на том же автомобиле в той же истории диалога.
Из-за бюджета сначала пилот на 1-2 сценариях; полный прогон допустим только если
предварительная верхняя оценка оставшихся затрат укладывается в 1 USD.

## Правила Результата

- Модель возвращает кандидата, а не юридически подтверждённое значение.
- Каждое число сопровождается исходной единицей и типом мощности: ДВС,
  суммарная гибридная, пиковая электрическая или явно указанная 30-минутная.
- Сохраняются оригинальный URL, тип и номер документа при наличии, страница
  PDF либо раздел HTML, короткий подтверждающий фрагмент, версия автомобиля,
  рынок и границы применимости. Номер страницы отсутствующего PDF не выдумывать.
- Недостающие VIN/год/рынок/модификация не восстанавливаются догадкой.
- Нет универсального коэффициента для получения 30-минутной мощности из пиковой.
- Суммарная мощность гибрида не подставляется в поле мощности ДВС.
- Совпадение модели без версии/рынка не подтверждает применимость значения.
- Брошюра производителя может подтверждать справочную характеристику, но не
  заменяет автоматически ОТТС/СБКТС/ЗОЕТС/ЭПТС применимого автомобиля.
- В пилоте любые найденные значения остаются вне автоматического расчёта.
- Если подтверждения нет, корректный результат: нет данных, нужна идентификация
  или есть противоречие. Самооценка уверенности модели не заменяет источник.
- Текст страниц и документов считается данными, а не инструкциями для модели.

## Проверка И Метрики

Проверять каждое утверждение по оригинальному источнику, не по поисковому сниппету.
Отдельно считать: наличие источника, применимость к автомобилю, правильность числа,
единицы и типа мощности, корректность отказа, время, использование токенов,
поисковых инструментов и стоимость. Ошибка смешения пиковой и 30-минутной мощности
является критической независимо от процента остальных правильных ответов.

Без независимо подтверждённого эталона сценарий является исследовательским,
а не числовым тестом точности. Не считать отсутствие ответа ошибкой, если
необходимых данных нет. Не делать вывода о пригодности для запуска по десяти примерам.

## Бюджет И Данные

Перед первым вызовом проверить актуальные тарифы выбранной модели и инструментов.
Ограничить число вызовов, выходные токены и поиск; учесть поисковый контекст,
неудачные запросы и повторные попытки. Не запускать запрос, если его консервативная
максимальная стоимость плюс уже зарезервированные расходы превышает остаток.
Если верхнюю оценку нельзя обосновать, платный запрос не выполнять.
Не делать автоматических повторов после сетевой неопределённости без проверки затрат.

Начальные запросы содержат только характеристики модели, без персональных данных
и реальных VIN. Документы с данными владельца перед отправкой нужно обезличить.
Не логировать ключ, заголовки авторизации или содержимое .env.

## Следующий Шаг

1. Настроить OPENAI_API_KEY через локальное окружение либо игнорируемый Git
   файл .env. Не публиковать ключи в переписке, коде, результатах и журналах.
2. Подготовить ограниченный исполнитель API и проверить его без сети на тестовых
   ответах: бюджет, отказ при отсутствии ключа, неполные источники и ошибки типов мощности.
3. Выполнить один реальный запрос, проверить ответ и затраты, затем решить,
   сколько дополнительных сценариев помещается в оставшийся бюджет.
4. Подготовить отдельный отчёт с реальными ответами. Шаг 2 roadmap не начинать
   без нового согласия пользователя.
